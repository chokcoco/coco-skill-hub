# Data Story Template / 数据故事模板

## Purpose / 用途

用来解释一个量如何变化、为何变化，以及读者应该怎样据此行动。它必须保留单位、方向、基线和观察条件。

Explain how a quantity changes, why it changes, and what readers should do with that result. It must retain units, direction, baseline, and observation conditions.

## Layout / 布局

- 只挑一条主趋势；若有第二指标，把它做成旁注而非第二张大图。
- 图表区域占主视觉，条件、样本和基线放在紧凑注释卡里。
- 颜色用于区分系列或区间，不能只为了好看。
- 若数据是示意，明确标为“示意数据”或“假设示例”。

- Choose one primary trend; put a second metric in an annotation rather than a second large chart.
- Let the chart own the visual area; place conditions, sample, and baseline in compact notes.
- Use color to distinguish series or ranges, never merely for decoration.
- If the data is illustrative, explicitly label it “illustrative data” or “hypothetical example.”

## Prompt Skeleton / 提示词骨架

```text
Create a technical data-story infographic titled “[title]”.
Primary measure: “[metric]”, unit “[unit]”, observed across “[axis/range]”.
Baseline: “[baseline]”. Conditions: “[sample, environment, or assumption]”.
Show the main trend and annotate [one or two] inflection points with “[cause or interpretation]”.
Add a concise action note: “[decision the reader can make]”.
Use readable axes, high-contrast labels, and the shared watercolor-and-ink visual language.
```

## Review / 验收

- 单位、时间/范围、基线和条件是否完整？
- 视觉是否把“相关”误画成“因果”？
- 图表结论是否能被旁注中的事实支撑？

- Are unit, time/range, baseline, and conditions complete?
- Does the visual mistakenly depict correlation as causation?
- Is the visual conclusion supported by the facts in the annotations?
