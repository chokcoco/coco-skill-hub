# 技术文本编辑边界

本文件只规定 Humanizer 编辑技术文本时的边界，不提供技术写作方法，不核验事实，也不裁定内容是否完整。

## 可以处理

- 宣传腔、口号、模板化过渡、机械排比、碎句和翻译腔。
- 为了表达自然所做的句序、措辞和段落节奏调整。
- 术语周围的冗余解释、无信息评价和不必要的比喻。
- 明显的表达性问题，例如指代不清、病句、拟人化措辞或同义词轮换。

## 必须保留

- 原文已给出的技术术语、版本、数字、限定条件、因果关系和机制说明。
- 正确的概念主体，例如谁调用、谁处理、谁消费或谁受影响。
- 代码块、命令、配置、API 路径、字段名、协议名和外部引用的原样内容。
- 中文技术社区稳定使用的英文术语，例如 `API`、`prompt`、`Agent`、`workflow`、`repo`、`diff`、`code review`、`CLI`。

## 发现问题时的处理

| 发现 | Humanizer 的动作 |
| --- | --- |
| 数字、版本或来源看起来可疑 | 标记“需事实核验”，不自行搜索、确认或替换。 |
| 结论缺少机制、前提或边界 | 标记“需补充内容”，不自行补写技术解释。 |
| 术语含义不明或概念主体疑似错误 | 标记“需领域审核”，不按猜测改术语。 |
| 例子像是杜撰 | 删除为制造氛围而新增的细节；原文案例则标记“需确认来源”。 |

## 编辑检查

1. 改写前圈出不可变内容：术语、数字、版本、条件、代码和机制。
2. 只改表达层问题，避免以“更好懂”为由把精确描述换成口语或比喻。
3. 改写后逐句比对，确认不可变内容没有丢失、弱化或换义。
4. 将发现的事实或内容缺口单列为风险，不把它们计入 Humanizer 已修复的成果。
