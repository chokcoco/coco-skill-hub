# Coco Humanizer-zh

把文本改得直接、准确、自然。去除的是空洞的造势、模板和翻译腔，不是专业术语、作者观点或必要的复杂性。

## 适用边界

- 用于使用中文编写的可见文本、教程、技术文档和中文改稿。
- 保留原文已经成立的事实、论点、术语、数据、概念主体和语气；只改存在问题的句子，不顺手重写无关段落。
- 不编造经历、案例、数字、来源或读者反馈来制造“真实感”。
- Humanizer 只判断表达质量。事实是否正确、教学目标是否达成、文件是否构建成功、内容是否发布，仍由相应的核验或人工审核负责。
- 代码块、行内代码、JSON 键名、URL、API 路径、字段名、配置项、命令和原文引用不做机械改写。

## 基本流程

1. 确认文本类型、目标读者、预期语气，以及这是新写还是改稿。
2. 阅读 [去 AI 味编辑规范](reference/de-ai-style.md)，按其中的固定流程处理所有中文任务。
3. 根据路由加载专项参考；不要为了“全面”一次读完全部材料。
4. 修改后回读问题句及其上下文，检查含义、逻辑、术语和指代没有被削弱或改错。
5. 交付改写文本；只有用户需要时，再简要说明改动理由或给出评分。

## 交付标准

- 先给具体信息或明确判断，删掉不增加信息的开场、过渡、评价和升华。
- 具体而不虚构：不新增未经原文或用户资料支持的细节、数字、来源或经历。
- 自然但不油滑：避免机械排比、二元纠正、短碎句堆砌、口号式结尾和聊天残留。
- 专业但不堆术语：术语用于准确表达，解释用于降低理解成本；不要把通行英文技术词强译成别扭中文。
- 改稿后能回答：原文的信息还在吗？必要的解释有没有被删掉？有没有引入新的事实、夸张或病句？

## 输出

默认提供改写后的文本。用户要求审阅而非直接改写时，按“原文 -> 建议 -> 类型”列出可定位的问题；不把泛泛的“更自然”“更有感染力”当作建议。

质量 Gate 还应按 `quality-rubric.md` 给出五维评分、扣分依据和是否达到课程正文的 45/50 标准。
