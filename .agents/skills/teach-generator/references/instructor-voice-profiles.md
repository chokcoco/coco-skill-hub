# 讲师语言风格

讲师风格只改变表达，不改变事实、来源、学习目标、前置要求和质量标准。每门课确定一个基础风格；章节最多增加一个局部修饰，并在课程 spec 或蓝图中记录。

## 严谨技术型

适合协议、语言语义、JVM、并发、事务、安全和架构边界。

- 先定义术语和适用条件，再给结论。
- 区分规范、实现、经验和教学简化。
- 用反例、实验或来源支撑容易误解的断言。
- 句子可以较密，但每段只推进一个判断。

避免把严谨写成晦涩：不堆术语，不把源码细节当作深度，也不省略零基础前置。

## 耐心教练型

适合零基础语言、标准库和首次接触某一领域的学习者。

- 从读者已经认识的对象开始，每次跨一个台阶。
- 新符号和操作及时解释，并给出可观察结果。
- 允许用短回顾连接前后知识，但不反复复述。
- 练习从预测和修改逐步过渡到独立完成。

避免把耐心写成居高临下。删除“你只需要”“其实很简单”“不要害怕”和作者内心独白。

## 实践带练型

适合环境安装、框架入门、工具使用、部署和综合实践。

- 先说明当前完成条件，再给操作。
- 每一步交代位置、动作和结果；关键节点停下来核验。
- 用真实错误信息和证据组织排错。
- 解释紧跟操作，不让理论与实际步骤分离过远。

避免变成命令清单。学习者仍应知道工具职责、关键配置为何存在，以及怎样判断结果可靠。

## 案例分析型

适合机制实验、故障诊断、性能分析和架构权衡。

- 保留现象、限制条件和原始证据。
- 明确提出可验证假设，按证据推进判断。
- 允许出现不确定性，但要说明如何缩小范围。
- 修复或决策后回到初始目标复盘。

避免先编造戏剧化事故再补概念，也不要把讲师知道答案后的推理伪装成真实调查过程。

## 简洁专业型

适合有明确前置的进阶课、参考资料、模块过渡和团队内部培训。

- 省略已经确认掌握的基础，不省略关键限定条件。
- 使用高信息密度的例子、表格和验收项。
- 直接给出选择标准，减少课堂式推进语。

避免把简洁变成跳步。课程任务定义没有证明学习者掌握某项前置时，仍需补充或链接到对应内容。

## 组合规则

基础风格决定整门课的声音，例如“耐心教练型”。局部修饰只改变当前任务，例如环境章可使用“耐心教练型 + 实践带练型”，JVM 章可使用“耐心教练型 + 严谨技术型”。不要叠加三个以上标签。

Humanizer 检查对所有风格有效。任何风格都不得依赖宣传语、机械三段式、虚构个人经历、随机口头禅或谄媚语气制造个性。
