# 语言基础与标准库类写法指引

## 适用范围

用于编程语言的语法、类型、表达式、控制流程、函数或方法、对象模型、错误处理、集合、标准库和语言运行规则。目标是让学习者能解释规则、阅读代码，并逐步独立编写或修改代码。

## 从知识依赖开始

先列出本章会出现的每个语法元素和库对象，标记哪些已经讲过。若示例必须提前使用一个概念，只补当前任务需要的最小语法，并明确完整内容会在哪一章展开。

第一份代码尽量短，一次观察一个规则。新符号第一次出现时解释含义；控制台输出、返回值、异常或状态变化要在相邻文字或注释中说明。完整程序结构只在确实需要运行时出现，不要让样板代码淹没新知识。

在必要的地方引出完整 API 表格列表，通过一个或者多个例子，譬如 String 的方法展示，引出完整的 String API 表格，对每个方法进行完整解释。课程可以只挑重点的 API 进行讲解，但是必要的完整 API 列表有助于保持课程的丰富度和严谨性。

## 可选择的推进路线

- 概念建模：已有概念 → 新对象定义 → 最小语法 → 运行结果 → 机制 → 边界 → 迁移应用。
- 对比辨析：两个容易混淆的规则分别建立 → 用最小反例观察差异 → 解释原因 → 给出选择标准。
- 标准库操作：对象用途 → 创建或取得对象 → 核心操作 → 返回值和状态 → 组合使用 → 复杂度、异常或可变性边界。
- 控制流程：执行顺序 → 单个结构 → 条件变化 → 嵌套或组合 → 可读性与退出边界。

这些路线可以重排。不要为了匹配模板强行加入业务场景、Mermaid 图、复杂源码或每一种 API。

## 从基础走向应用

应用场景放在基本规则已经成立之后，只引入少量业务词汇。场景的作用是让学习者迁移刚学到的规则，而不是展示作者能写多大的 Demo。

进阶内容要解释它为何与当前基础有关。例如相等性章节可以提前说明 `hashCode` 契约，但不必把哈希集合的所有实现细节搬进来。明确本章讲到哪里、后续章节接着讲什么。

## 练习与反馈

从预测输出、解释原因、修改一行代码、补全短程序逐步走向独立编写。答案应指出判断依据；只给最终输出无法检验是否理解。涉及关系或执行过程时，可以要求画引用图、作用域图或调用顺序。

## 常见失败

- 用完整业务 bug 开场，让零基础读者先猜规则。
- 一次引入类、方法、集合、泛型和异常，再逐行解释。
- 只罗列语法和 API，没有说明执行结果与适用边界。
- 每章机械使用相同的小节名和相同数量的示例。
- 为达到篇幅加入重复代码、百科历史或未服务学习目标的源码分析。
