# 语感样本库：Claude Code 中文文档 × 智谱开放文档

> 与 `docs/写作规范.md` §三「语感锚定基线」配套（2026-09-04 建库）。分工：量化基线回答「不像 AI 味的底线在哪」（句长/标点/引号），本库回答「像官方技术文档该怎么写」——按句式类型收录两份官方文档的**逐字原文例句**、句式骨架与适用场景。课程（courses/）与教程（series/、无系列）通用。

## 怎么用（写作/改写前，写作规范 step 0 已挂接）

1. 判断本节稿子以哪种句式为主：新概念登场→读「定义句」；功能介绍/能力说明→「能力陈述句」；操作步骤→「指令建议句」；取舍解释→「因果条件句」；新旧对比/概念辨析→「对比句」；坑与限制→「边界警示句」；原理机制→「机制过程句」。
2. 默读对应类别的 2–4 条例句两遍找语感，再动笔。目标是让「官方文档会怎么写」取代「我习惯怎么写」。
3. 不是抄句子：学「句式骨架」的组织方式，用自己的技术内容填空。
4. 写完后照旧用量化基线 + `scan-ai` / `scan-lexicon` 收尾；语义层问题仍走固定流程第 9 步。

## 一、定义句

**何时用**：核心概念/术语首次登场，先给一个能核查的定义再展开；定义句不带评价词、不给形容词堆砌。

> Claude Code 是一个由 AI 驱动的编码助手，可帮助你构建功能、修复错误和自动化开发任务。
> — Claude Code 概览（https://code.claude.com/docs/zh-CN/overview）

骨架：`X 是一个……的<类别>，可帮助你 <动宾>、<动宾>、<动宾>。`——三个动宾短语界定职责范围，零形容词。

> Claude Code 充当 Claude 周围的**代理框架**：它提供工具、上下文管理和执行环境，将语言模型转变为能够进行编码的代理。
> — Claude Code 如何工作（https://code.claude.com/docs/zh-CN/how-claude-code-works）

骨架：`X 充当……：它提供 A、B 和 C，将……转变为……。`——冒号展开式定义，「定义即交代构成要素与作用链」。

> Token 是模型用来表示自然语言文本的基本单位，可以直观的理解为“字”或“词”；通常 1 个中文词语、1 个英文单词、1 个数字或 1 个符号计为 1 个 token。
> — 智谱·平台介绍（https://docs.bigmodel.cn/cn/guide/start/introduction）

骨架：`X 是……的基本单位（定义）；<分号后接计数口径/落地说明>。`——先定义后给口径，与写作规范「先定义后展开」同一条。

> 文本模型是一类专注于处理和生成自然语言的模型，涵盖了语言理解与推理能力，能够自动处理海量文本数据并进行逻辑推导。
> — 智谱·模型概览（https://docs.bigmodel.cn/cn/guide/start/model-overview）

骨架：`X 是一类……的模型，涵盖了……，能够……并进行……。`——定义 + 能力 + 动作一次交代，主谓完整。

## 二、能力/状态陈述句

**何时用**：说明工具/模型/平台「能做什么、现在是什么状态」。用可观察的动作与事实名词，不用「强大/先进/赋能」这类评价词。

> Claude 可以读取任何语言的代码、理解组件如何连接，以及找出需要改变什么来实现您的目标。
> — Claude Code 如何工作

骨架：`<主体> 可以 <动作>、<动作>，以及 <动作>。`——动词并列，宾语全具体，能力边界靠可观察动作说明。

> Claude 的 context window 保存你的整个对话，包括每条消息、Claude 读取的每个文件和每个命令输出。
> — Claude Code 最佳实践（https://code.claude.com/docs/zh-CN/best-practices）

骨架：`<X> 保存/包含……，包括每个 <A>、每个 <B> 和每个 <C>。`——用「包括…的每个…」逐项枚举坐实含义，信息密度靠列举而非形容词。

> 平台已上架数十个模型，覆盖文本生成、语言推理、图像理解、视频生成、音视频处理等多场景。
> — 智谱·平台介绍

> 平台提供多种模型，您可以根据自己的需求选择合适的模型。
> — 智谱·快速开始（https://docs.bigmodel.cn/cn/guide/start/quick-start）

骨架（供给—选择式）：`平台提供……，您可以根据……选择……。`——陈述而非推销。

**反例（营销腔与 AI 味同源，课程别学）**：智谱官方文档的宣传段自身也这样写——「功能丰富、灵活易用、高性价比」「先进的预训练技术……优秀的语言理解、文本生成和复杂推理能力」「普惠的全球前沿模型」。这类句子建库时主动排除；能力陈述宁要 dry 的事实句。

## 三、指令/建议句

**何时用**：教读者「怎么做」。先圈定适用场景再给动作；「请/建议/要求」直接上，不靠感叹号或口号。

> 对于范围明确且修复很小的任务（如修复拼写错误、添加日志行或重命名变量），要求 Claude 直接执行。
> — Claude Code 最佳实践

骨架：`对于 <范围>（如 <例>），<动作>。`——指令自带条件与例证，括号把抽象范围具象化。

> 让 Claude 显示证据而不是声称成功：测试输出、它运行的命令及其返回的内容，或结果的屏幕截图。
> — Claude Code 最佳实践

骨架：`让 <X> <动作> 而不是 <空话>：<可核验证据清单>。`——正反对照 + 冒号罗列判据。

> 请妥善保管您的 API Key，不要泄露给他人，也不要直接硬编码在代码中。建议使用环境变量或配置文件来存储 API Key。
> — 智谱·快速开始

骨架（先禁后荐）：`请 <正面要求>；不要 <A>，也不要 <B>。建议 <正解>。`——先划红线再给正向替代。

> 建议实现适当的错误处理和重试机制，特别是对于 429 和 500 错误。
> — 智谱·快速开始

> 建议 `temperature` 和 `top_p` 只使用其中一个。
> — 智谱·核心参数（https://docs.bigmodel.cn/cn/guide/start/concept-param）

骨架（建议带限定）：`建议 <做法>，特别是对于 <精确对象>。`——落到可执行层面，这是泛泛而谈最缺的细节。

## 四、因果/条件句

**何时用**：解释「什么条件下怎样做更合适、为什么」。条件前置、机制给全、结论落在可执行处。

> 如果单个文件或工具输出太大，以至于在每次总结后上下文立即重新填充，Claude Code 会在几次尝试后停止自动压缩，并显示错误而不是循环。
> — Claude Code 如何工作

骨架：`如果 <条件>，以至于 <后果>，<X> 会 <对策>，并 <兜底> 而不是 <死循环>。`——触发条件、对策、底线一次讲完。

> 影响远程系统的操作（数据库、API、部署）无法进行 checkpointing，这就是为什么 Claude 在运行具有外部副作用的命令之前询问。
> — Claude Code 如何工作

骨架（动机解释）：`<技术限制>，这就是为什么 <设计行为>。`——解释设计动机不搬口号。

> 在需要严谨、事实准确的场景（如知识问答），建议使用较低的 `temperature`。
> — 智谱·核心参数

骨架（场景前置建议）：`在 <场景>（如 <例>），建议 <做法>。`

> GLM 系列模型中 token 和字数的换算比例约为 1:1.6，但因为不同模型的分词不同，所以换算比例也存在差异，每一次实际处理 token 数量以模型返回为准，您可以从返回结果的 usage 中查看。
> — 智谱·平台介绍

骨架（原因→口径→查证）：`因为 <原因>，所以 <存在差异>；以 <权威来源> 为准，可从 <查证途径> 查看。`（注意：换算数字官方文档自身口径漂移，见附录 B，引用只学句式不传数字。）

## 五、对比句

**何时用**：讲清「和 X 有什么不同」。差异点用可观察行为或定义差异，不用「更强更好」。

> 与等待回答问题的聊天机器人不同，Claude Code 可以读取你的文件、运行命令、进行更改，并在你观看、重定向或完全离开的情况下自主解决问题。
> — Claude Code 最佳实践

骨架：`与 <A> 不同，<B> 可以 <动作>、<动作>、<动作>，并 <状语> 地 <动作>。`——差异点全为可观察行为。

> ……这与只看到当前文件的内联代码助手不同。
> — Claude Code 如何工作（承接前文动作链后点破差异）

> 视觉理解模型侧重于看懂图像内容，如识别物体、场景和关系；而视觉推理模型进一步具备看图思考的能力，能结合视觉与语言信息完成逻辑判断、因果分析和多步推理，常用于图文问答、图像描述生成、多模态对齐等复杂任务。
> — 智谱·模型概览

骨架（递进对比）：`<A> 侧重于 <能力>，如 <例>；而 <B> 进一步具备 <能力>，能 <动作>，常用于 <场景>。`——对比中夹能力清单与适用场景，长而不断。

> 最大输出 Tokens 是指模型在单次请求中能够生成的最大 Token 数量。它与 `max_tokens` 参数不同，`max_tokens` 是您在请求中设置的上限，而最大输出 Tokens 是模型本身的架构限制。
> — 智谱·核心参数

骨架（概念辨析）：先各给定义，再 `它与 <参数> 不同，<参数> 是 <你的设置>，而 <X> 是 <架构限制>。`——用「您设置的/模型本身的」两极对照切开易混概念。

## 六、边界/警示句

**何时用**：讲「什么情况下会出问题、什么不是」。平铺直叙讲失败模式与边界，不渲染、不吓唬、不做吞吞吐吐的免责声明。

> 对于使用 `-p` 标志的非交互运行，如果分类器重复阻止操作，auto mode 会中止，因为没有用户可以回退到。
> — Claude Code 最佳实践

骨架：`对于 <模式>，如果 <触发条件>，<X> 会 <停止>，因为 <原因>。`——把「中止」当设计内行为平静写出并交代原因。

> 默认配置下，Claude Code 需要能够访问 claude.ai 和 Anthropic API 等端点才能完成安装、登录和正常使用。在中国大陆的网络环境中，这些端点可能无法直接访问。
> — Claude Code 概览

骨架：`默认配置下，<X> 需要 <前置条件>。在 <环境> 中，<限制>。`——先前提句划边界，再陈述句交代地域限制。

> 注意: `max_tokens` 限制的是生成内容的长度，不包括输入。
> — 智谱·核心参数

骨架：`注意：<X> 限制的是 A，不包括 B。`——直接纠正常见误解，只划「是什么/不是什么」的边界。

> 如果输入和期望输出的总长度超过了模型的上下文窗口，模型将无法处理。
> — 智谱·核心参数

> 如果模型在达到 `max_tokens` 限制前完成回答，会自然结束；如果达到限制，输出可能被截断。
> — 智谱·核心参数（原页为 `max\_tokens` 转义写法，引用时还原反斜杠）

骨架（双分支）：`如果 <未达限制>，会 <正常结果>；如果 <达到限制>，可能 <异常结果>。`——正常结束 vs 截断一次讲清。

## 七、机制/过程陈述句

**何时用**：讲内部如何运作。先给阶段/构成总数再展开，主语一贯、零评价。

> 当您给 Claude 一个任务时，它会经历三个阶段：**收集上下文**、**采取行动**和**验证结果**。
> — Claude Code 如何工作

骨架：`当 <触发> 时，<X> 会经历 N 个阶段：A、B 和 C。`——先给总数再冒号引出阶段名。

> Claude 根据从前一步学到的内容决定每一步需要什么，将数十个操作链接在一起并沿途进行纠正。
> — Claude Code 如何工作

骨架：`<X> 根据 <依据> 决定 <动作>，将 <动作链> 并 <自我修正>。`——决策依据、动作、规模一次到位。

> `top_p`（核采样）通过从累积概率超过阈值的最小 token 集合中进行采样来控制多样性。
> — 智谱·核心参数

骨架：`<术语>（<别称>）通过 <过程> 来控制 <目标>。`——把机制压缩进一个主谓宾，术语精确（核采样、累积概率超过阈值）。

## 八、其他可复用句式（边角料）

> 与其自己编写代码并要求 Claude 审查，不如描述你想要什么，让 Claude 弄清楚如何构建它。
> — Claude Code 最佳实践（取舍式建议：`与其 <A>，不如 <B>。`）

> 虽然 Claude 有时会在第一次尝试时完美地解决问题，但快速改正它通常会更快地产生更好的解决方案。
> — Claude Code 最佳实践（让步转折：`虽然 <A>，但 <B> 通常会 <更好结果>。`先让一步再立论）

> 内置工具通常分为五个类别，每个类别代表不同类型的代理能力。
> — Claude Code 如何工作（分类总起：`<X> 通常分为 N 类，每类代表 <差异>。`）

> 在第十次批准后，你不是真的在审查，你只是点击通过。
> — Claude Code 最佳实践（直白评论句：全篇书面语中偶插一句直白判断，收「克制的人话」之效；22 字，未达 25 字正选线，句式价值高所以收录）

> 希望模型生成更多样、更有趣的内容时，设为 `true`，并配合 `temperature` 或 `top_p` 使用。
> — 智谱·核心参数（条件状语+祈使。配套对偶句：需要可复现、确定性的输出时，设为 `false`。——AI 写手最爱把这种结构抻碎成两段啰嗦，官方文档两行收完）

## 附录 A：反例对照（营销腔与 AI 味同源）

智谱官方文档宣传段自身也出现与 AI 味同源的句子，建库时**主动排除**，课程写作也不学：

- 「功能丰富、灵活易用、高性价比的大模型 API 服务」（平台介绍宣传段）
- 「先进的预训练技术……具备优秀的语言理解、文本生成和复杂推理能力」（模型介绍宣传段）
- 「普惠的全球前沿模型」（模型概览宣传段）

判断标准：**去掉它句子还完整吗、能核查吗**——不能核查的评价词堆砌就是腔调。

## 附录 B：口径与术语漂移警示（不当作事实引用）

- token 换算比例官方文档自身口径不一致：平台介绍页说「1 个中文词语≈1 个 token」，核心参数页说「1 个令牌约等于 0.75 个英文单词或 1.5 个中文字符」，且一处称 token、一处称「令牌」。引用这类句子只学句式，**数字与术语一律以写作时官方最新口径核对**（写作规范 step 2 事实核查）。
