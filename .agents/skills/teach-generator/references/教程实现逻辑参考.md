教程实现逻辑：

1. 先找素材 - 从知识点、QA题目、已有Wiki、资源库、外网搜索里收集相关内容
2. 规划大纲 - 像写书一样，先定章节结构、每章讲什么
3. 逐章生成 - 用 LLM 写成真正的教程文章
4. 质量把关 - 自动检查质量，不合格就重写
5. 发布审核 - 质量好的自动发布，差的人工审核

---

🔄 完整流程（五步走）

第一步：收集素材（source.ts）

目标：把知识点相关的所有材料都找出来

素材来源（五路并进）：

1. 知识点树 - 这个知识点本身和它的子知识点
2. QA 题目 - 题库里相关的题目和答案（核心素材）
3. 站内 Wiki - 之前写过的相关文章
4. 资源库 - 课件、文档里的相关片段
5. 外部检索 - 从网上搜官方文档、中文技术文章（可选）

关键代码位置：lib/tutorial-generation/source.ts 里的 loadTutorialSourceBundle

---

第二步：规划大纲（planner.ts + outline.ts）

目标：决定要写几章、每章讲什么、用哪些素材

规划策略：

+ 叶子知识点（没有子节点）：生成 1-8 篇文章的平铺结构
+ 目录知识点（有子节点）：生成章节结构，最多 45 篇文章
    - 每个一级子知识点变成一个章节
    - 章节下再根据二级子知识点拆分文章

关键常量：  
const HARD_MAX_ARTICLES = 8           // 平铺结构最多 8 篇  
const HARD_MAX_TOC_ARTICLES = 45      // 章节结构最多 45 篇  
const MAX_ARTICLES_PER_SECTION = 4    // 每个章节最多 4 篇文章

Prompt 调用点：lib/tutorial-generation/outline.ts 里的 generate

+ Prompt 名称：tutorial_outline_generate
+ 输入：知识点树、QA 题目、上下文摘要
+ 输出：完整的教程大纲（JSON 格式）

---

第三步：逐章生成（chapter-generator.ts）

目标：把每个章节计划变成真正的教程文章

核心逻辑：

1. 上下文筛选 - 从全部素材里挑出这章需要的（context-select.ts）
2. 构建 Prompt - 把章节计划、素材、质量要求都塞进去
3. 调用 LLM - 生成 Markdown 格式的教程文章
4. 兜底机制 - LLM 失败了就用模板生成基础版本

Prompt 名称：tutorial_chapter_generate

Prompt 核心内容（简化版）：  
【输入】

+ 系列标题和章节标题
+ 章节计划（学习目标、必须覆盖的知识点）
+ 知识点树
+ QA 题目素材（最重要）
+ Wiki 上下文
+ 资源片段
+ 外部检索结果
+ Evidence 引用列表（可追溯来源）

【要求】

1. 写成"背景动机 → 概念解释 → 原理拆解 → 边界误区 → 实践建议 →
2. 每章优先围绕 1-2 个核心机制讲透，不要平均铺开
3. 3 项以上对比必须用 Markdown 表格
4. 需要图形时只用 Mermaid（flowchart/sequenceDiagram/stateDiagram），禁止 mindmap
5. 涉及技术更新、版本演进必须有 evidence 支撑
6. 核心术语用 blockquote Tips 解释
7. 补充最佳实践、排查清单、典型场景
8. 不要输出 QA 题目的原始字段结构（如 follow_up_questions）

【质量增强指令】

+ 不能只是问答堆砌，要转化为连续的学习路径
+ 真实事故、具体版本号、URL 必须由 evidence 支撑，不得编造
+ 正文不能暴露内部 item_id、ref_id 等字段

兜底 Markdown 模板：  
如果 LLM 调用失败，会生成一个基础模板，包含：

+ 学习目标
+ 核心概念列表
+ Tips 提示框
+ 实践检查清单
+ 自测练习（从 QA 素材提取）

---

第四步：质量检查（qc.ts）

目标：自动判断文章质量，决定能不能直接发布

两层 QC 机制：

1. 确定性 QC（规则检查，必过）

不需要调用 LLM，纯代码检查：

硬性失败条件（任何一条命中就拒绝）：

+ 内容太短（< 800 字）
+ 代码块没闭合（``` 数量不匹配）
+ 没有任何 evidence 引用
+ 正文暴露了内部 ID（UUID、source_item_ids、ref_id）
+ 出现了禁止的 "QA 来源清单"
+ 使用了禁止的 Mermaid mindmap 图表
+ 出现了未在 evidence 中提供的外部 URL

评分维度（0-1 分）：

+ grounding_score（0.26 权重）- 内容与素材的匹配度
+ coverage_score（0.20 权重）- 必须覆盖的知识点覆盖率
+ course_depth_score（0.16 权重）- 文章深度（基于长度）
+ structure_score（0.13 权重）- 必需章节完整性（学习目标、核心概念、原理、误区、小结）
+ readability_score（0.09 权重）- 可读性（固定 0.75）
+ source_quality_score（0.06 权重）- 来源质量（有官方文档加分）
+ learning_aids_score（0.05 权重）- 学习辅助工具（表格、图表、T
+ practice_relevance_score（0.03 权重）- 实践相关性（最佳实践、排查清单）
+ freshness_score（0.02 权重）- 时效性（涉及版本更新时检查来源
2. LLM QC（语义检查，可选）

调用 LLM 做更深入的质量判断

Prompt 名称：tutorial_chapter_qc

LLM 检查重点：

+ 确定性 QC 无法判断的语义问题
+ 知识点覆盖的细粒度分析
+ 断言和结论的支撑度
+ 文章结构和逻辑连贯性

最终决策：  
if (硬性失败 || 评分 < 0.7 || grounding < 0.35) {  
  return 'reject'  // 拒绝发布  
} else if (评分 >= 0.85 && grounding >= 0.9 && coverage >= 0.8) {  
  return 'auto_publish'  // 自动发布  
} else {  
  return 'manual_review'  // 人工审核  
}

重试机制：

+ QC 失败的文章会重新生成，最多 3 次
+ 每次重生成时会把 QC 反馈（qc_feedback）作为额外指令传给 LLM

---

第五步：发布审核（publisher.ts）

目标：根据 QC 结果和发布策略，决定是否发布

发布策略（三种）：

1. auto - 全自动，QC 通过就发布
2. manual - 全人工，都需要审核
3. hybrid - 混合，QC 高分自动发布，中等分人工审核

发布流程：

1. 将文章写入 wiki_publications 表（Markdown 存数据库）
2. 在 wiki_series_items 中建立系列与文章的关联
3. 如果是自动发布，设置 status = 'published'
4. 如果需要人工审核，设置 review_status = 'needs_review'

---

🔧 任务调度（jobs.ts）

并发控制：

+ 系列生成任务：最多 3 个并发（teamSize: 3）
+ 章节生成任务：最多 6 个并发（localConcurrency: 6）
+ 全局并发限制：最多 5 个系列同时生成（业务层流控）

超时保护：

+ 系列生成：2 小时超时
+ 章节生成：30 分钟超时
+ 数据库层：48 小时未完成自动标记失败

取消机制：

+ 用户可以随时取消任务（status = 'cancelled'）
+ 系列生成和章节生成都会在多个检查点检查取消状态
+ 已发起的章节任务会在入口处提前退出

📊 数据存储

核心表：

1. tutorial_generation_jobs - 任务追踪表
2. wiki_series - 教程系列表
3. wiki_series_items - 系列目录表（章节和文章的树形结构）
4. wiki_publications - 文章内容表（Markdown 存这里）

关键字段：

+ source_type = 'qa_tutorial' - 标记为 QA 教程生成
+ generation_job_id - 关联到生成任务
+ source_item_ids - 记录用了哪些 QA 题目
+ qc_score / qc_result - QC 结果
+ review_status - 审核状态
