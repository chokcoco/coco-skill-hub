# 环境安装与工具准备类结构模板

这份模板提供环境章节的可选骨架。不要把所有模块都写进正文；按目标系统、工具依赖和学习者起点选用。

## 使用前填写

- 最终可观察结果：`[...]`
- 支持的操作系统与架构：`[...]`
- 版本基线与兼容范围：`[...]`
- 必需工具及其依赖顺序：`[...]`
- 官方来源与核验日期：`[...]`
- 本章不处理的环境：`[...]`

## 推荐主线

### 1. 完成后的结果

给出两到五项明确验收，例如版本输出、生成文件、运行页面、服务状态或 IDE 控制台结果。

### 2. 工具与关系

只介绍本章会安装的工具。说明各自职责、为什么需要，以及它们怎样连接。需要选择工具时给出适用人群和取舍，随后明确课程默认方案。

### 3. 安装前检查

检查已有版本、CPU 架构、权限、磁盘、端口或前置包管理器。根据结果决定“保留并配置”“升级”“并存”还是“全新安装”。

### 4. 分系统安装

分别写 macOS、Windows 和课程明确支持的其他系统。每条路径包含：官方下载入口、版本与安装包选择、安装步骤、需要保留的选项、安装后的第一个核验结果。

### 5. 配置与逐项核验

按依赖顺序配置路径、环境变量、IDE、构建工具和项目设置。每完成一层就核验，不把所有配置留到最后一起调试。

### 6. 最小成果

运行能覆盖整条工具链的最小成果。说明文件放在哪里、命令在哪里执行、成功后会出现哪些输出或文件。

### 7. 排错路径

按“现象 → 收集证据 → 判断依赖层 → 只修改一项 → 重新核验”组织。保留真实命令和错误格式，不写泛泛建议。

### 8. 验收记录与下一步

用表格或清单记录版本、路径和结果。明确哪些条件满足后才能进入下一章。

## 可选变体

- 已有环境优先：先统一核验，再只补失败项。
- 远程或容器环境：先说明与本机路径的差异，再提供连接和持久化检查。
- 多版本并存：先解释选择器和生效范围，再分别核验终端、IDE 与构建工具。

## 交付前检查

- 每个受支持系统是否都有从下载到验收的完整路径？
- 所有立即使用的入口是否在对应步骤中直接链接？
- 每条命令是否写明执行位置和预期结果？
- 版本、链接和工具行为是否使用最新官方资料核验？
- 删除背景知识后，操作是否仍然完整；删除操作后，剩余解释是否都服务于排错和选择？
