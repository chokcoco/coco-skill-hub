# 原理阐述+结合已有源码进行教学类结构模板

先确认本章主教学任务为“概念讲解 + 源码对照”。正文以原理为主线，用教学最小实现建立可运行闭环，再用项目真实源码切片解释工程取舍。路径可以组合，但不能把 A、B 全部完整串联。

## 使用前填写

- 本章要建立的原理/机制：`[...]`
- 用到的公开资料：`[官方文档/规范/论文/...]`
- 教学最小实现的输入与输出：`[...]`
- 可引用的项目源码范围（已实现 / 目标方向 / 教学简化）：`[...]`
- 教学版与真实版的主要差异（至少三条）：`[...]`
- 源码引用中禁止出现的内部信息：`[...]`

## 路径 A：先原理后切入源码（新概念引导）

1. 用一个可观察现象或具体问题引出本章要解释的机制。
2. 逐段建立参与对象、状态、输入输出与边界条件，所有术语首次出现时引用讲解。
3. 写一份教学最小实现，用 Fake 或离线方式跑通，打印可观察结果并逐行解释关键逻辑。
4. 切入项目真实源码切片：选一个或两个文件/函数，说明它如何对应教学版中的某段逻辑、多做了什么工程处理。
5. 在源码切片下方用三段式引用备注给出 repo 相对路径（对应源码 / 模块阅读收益 / 当前源码注释），需要时逐条换行。
6. 对照一个差异表：教学版 vs 真实版，每条差异说明省略/增强原因与适用场景。
7. 指出两条常见误解（例如“Schema 通过就等于事实正确”“模型输出的 JSON 就能直接写文件”），并说明真实源码中如何防御。
8. 完成证据：用一段判断或实验，让学习者确认自己能否对照差异表读源码并说出取舍。

## 路径 B：先看真实源码再抽原理（逆向推导）

1. 展示一段项目真实代码，标注状态（已实现 / 目标方向）。
2. 从代码中提取三个关键设计决策，逐条解释背后的原理。
3. 用教学最小实现“复现”其中一段逻辑，剥离其余工程细节。
4. 比较教学实现与真实实现的差异，给出省略表。
5. 修改教学实现中的一个边界（例如增加超时配置、引入错误分类），观察行为变化并验证。
6. 回到真实源码，定位这次改动在真实代码中对应的位置。
7. 完成证据：用修改后的教学实现跑一次对比，产出可观察差异，并说明真实代码为什么比修改版多了某处处理。

## 可选模块

- **源码导航表**：一行一个文件路径，每个文件一句话职责说明 + 状态标签。
- **差异对照表**：教学版做了什么 / 真实版多做了什么 / 为什么 / 教学版是否可升级。
- **反模式集**：列出该主题在 Agent 初学者项目中的常见错误，并对照真实代码如何避免。
- **逐步改造练习**：给出一段教学代码，指定一个升级目标（如“加入 expected_hash 校验”），让学习者在真实源码参考下完成改造。

## 图与代码的使用

原理部分可用 Mermaid 画参与对象与关键因果链，但每个节点都必须有对应的教学代码或实验支撑。源码切片不要求完整文件，应紧扣当前教学点，旁注解释少于三行的块直接归入正文描述。不得为了代码量堆砌未加解释的大段源码。

## 交付前检查

- 教学最小实现是否真正可运行（用 Fake 不依赖网络和真实凭据）？
- 每个源码切片是否标注了状态（已实现 / 目标方向）并给出 repo 相对路径？
- 代码块下方是否有三段式引用备注，分别说明“对应源码 / 模块阅读收益 / 当前源码注释”（教学简化版必须在第三段说明简化了什么）？
- 差异对照表是否至少包含三条明确差异？
- 正文是否有“真正/确实/实际上”等 AI 味词、是否有“不是 X 而是 Y”句式超过两次？
- 是否存在把目标方向说成当前已实现、或泄露内部路径/凭据/本机绝对路径的情况？
