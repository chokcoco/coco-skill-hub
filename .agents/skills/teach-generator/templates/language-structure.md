# 语言基础与标准库类结构模板

这份模板用于设计认知顺序，不要求正文出现同名标题。根据知识点选择概念建模、对比辨析、标准库操作或控制流程路径。

## 使用前填写

- 本章核心规则或对象：`[...]`
- 学习者已经掌握的语法：`[...]`
- 示例中可能越级的内容：`[...]`
- 本章必须讲清的基本用法：`[...]`
- 需要触及的机制与边界：`[...]`
- 后续章节依赖：`[...]`

## 路径 A：概念建模

1. 从已知对象进入，定义新概念及其组成。
2. 给出最小语法或最小对象创建方式。
3. 运行短示例，观察一个确定结果。
4. 拆解赋值、调用、状态或执行过程。
5. 增加一个变化条件，说明常用方式。
6. 用反例建立边界和易错点。
7. 在已有上下文中迁移到简单应用。

## 路径 B：对比辨析

1. 分别定义两个容易混淆的对象或规则。
2. 用最小示例确认各自行为。
3. 让两者在同一个条件下产生不同结果。
4. 解释差异来自类型、状态、作用域、求值或运行机制的哪一层。
5. 给出选择问题，而不是只给“记住区别”。
6. 通过预测和修改练习确认学习者能独立判断。

## 路径 C：标准库操作

1. 说明对象解决什么问题，并与已知类型建立联系。
2. 展示创建、取得或转换对象的最小方式。
3. 逐项介绍高频操作，每次说明参数、返回值和状态变化。
4. 组合两到三个操作解决一个小任务。
5. 解释可变性、空值、异常、复杂度或资源释放等相关边界。
6. 给出 API 阅读和独立修改练习。

## 可选模块

语法表、内存或执行图、版本差异、反例、应用迁移、常见误区、练习、总结和自测。它们只在能检验学习成果时出现。

## 代码递进检查

- 第一份代码是否一次只引入少量新符号？
- 每个新符号是否在使用前或紧邻位置解释？
- 输出、返回值、异常和对象变化是否可观察？
- 完整程序是否只包裹已经解释的核心片段？
- 业务案例是否晚于基础规则，并且没有偷偷增加新框架？

## 交付前检查

- 学习者能否用自己的话解释规则，而不只是复述语法？
- 是否从阅读和预测逐步走向修改与独立编写？
- 进阶内容是否服务当前基础，并明确后续边界？
- 标题是否准确描述知识点，而不是模板占位词？
